# Agent Note: 年度账本结转

Status: implemented

## Problem

家庭需要按年度分开记账，同时继续使用跨年仍存在的资金、欠款、次卡和自动账单。旧账本应能长期查阅，也可由所有者日后永久删除。新账本的日常操作和报表需要在旧账本删除后继续成立。

## Decision

- 期末快照排除目标年创建的账户与手工借贷，确认批次要求先处理这些记录及规则引用的不可用账户。已删除的跨年扣款按来源规则及原计划期次找回，接续游标回到最早受影响的期次。迁移前的周期流水缺少计划期次，使用现有规则的账户、类型和备注匹配历史流水。
- 指定债务结算把债务引用写入还款流水，并在同一批次更新账户和借贷。指定还款先冲减对应债务，普通还款按同币种期初 FIFO 分配，剩余部分逐笔折算本币。汇总按逐笔流水重算时保留指定债务关联。

- 账本所有者通过「账本管理」或 `/api/open/ledgers/:id/rollover` 预览、确认年度结转。默认目标为站点时区的当前年份，已结转生成的账本接续下一年。可提前预览下一年，元旦起可确认。Web 确认后重签会话 Cookie 并切换到新账本。OpenAPI 保留已有令牌的默认账本，并提示为新账本签发令牌。
- 截止时点是目标年的前一年 12 月 31 日 23:59:59。预览和确认以账户实存余额 `balance_cents` 为基线，扣回目标年元旦起未删除活流水的带符号账户侧增量，保留各账户原币和信用卡负余额。冻结导入流水（`source = 'kap-import'`）没有变动实存余额，因此不参与扣回。新年度流水、缺少账户原币金额的旧年度流水、截止后的次卡活动和未处理的旧年度规则期次仍按各自条件阻止确认。活跃账户和非零余额归档账户承接期末余额，归档账户保留状态。新账户的期初从目标年元旦起参与报表。
- D1 在同一个事务批次中重查阻断条件、计算期初、创建新账本、复制关联数据、停用旧规则和归档旧账本。旧账本通过 `rolled_over_to_id` 保存结转结果。相同年度的重试返回原目标，结转归档后保持只读。新账本的数据和期初不引用旧账本，删除旧账本只清理旧数据及其令牌。
- 自定义分类的父子引用、账户引用和周期明细使用新账本记录，共享系统分类保留原引用。成员、角色和标签随账本承接。未结债务在新账本保存 `opening_cents`，同方向、同往来对象、同币种的还款优先冲减期初，再参与普通借贷汇总。同组多笔期初按入账顺序冲减。次卡仅承接元旦仍有效的剩余次数，保留原有效期，购卡和核销历史留在旧账本。预算和储蓄目标由用户重新设定。
- 周期规则和订阅保留计划日及原周期。试用订阅的接续计划日取现有计划与试用结束日中较晚的日期。旧年未处理期次由所有者在结转前核对；已经按正确计划日入账的期次使用推进后的游标。新年度到期的期次继续按计划日入账，只提醒的项目保持提醒。期次推进、流水插入及账户增量在同一批次提交，提交条件包括账本仍活跃、期次仍匹配。次卡扣减或续费也在同一批次写入台账和日志，关联续费支出随批次提交。
- 预览和确认对有效或试用订阅采用相同的账户和期次条件。只有 `auto_renew = 1` 的订阅必须绑定账户，任何已绑定的账户都必须存在于当前账本且未归档。非标准续费标记在预览、调度及 OpenAPI 读取中按仅提醒处理，Web 和 OpenAPI 写入时将显式传入的非标准标记归一化为 `0`，结转复制也将非标准标记归一化为 `0`。仅提醒订阅与自动续费订阅采用相同的旧年期次检查。有效订阅、试用已在旧年结束或缺结束日的订阅，其未处理期次早于元旦时阻止确认。
- 归档账本可切换、查阅、生成报表和导出。普通 Web 与 OpenAPI 写入口拒绝归档账本。账本状态也作为写入 SQL 的条件，防止已通过鉴权的请求与结转竞争。流水和附件的永久删除在清理 R2 前取得删除声明，确认结转时等待用户完成已开始的删除。后台业务调度排除归档账本。所有者仍可按原流程永久删除账本及已知 R2 对象。

## Alternatives considered

- **沿用推进后的游标和同组还款平均汇率**。可直接复制规则并沿用较短的汇总 SQL。软删扣款后会漏扣原期次，跨汇率还款也会把期初消耗的本币金额错分到本期债务，因此使用计划期次关联和逐笔折算。

- **按点击结转时的余额生成新账本**。可以直接采用当前余额，操作日期灵活，计算量也小。元旦后才操作时，已经记入旧账本的新年流水会混入期初，因此选择按旧年最后一个记账日计算。
- **按流水从期初正推**。已完整入账的流水可逐笔解释余额变化。冻结导入流水只保存历史，账户期初也可能是手录快照，因此结转从实存余额扣回新年活流水。
- **首版只承接资金账户余额**。复用现有账户期初字段即可，涉及的数据少。跨年未结应收应付和仍有效次卡需要重新登记，后续还款与核销也缺少可继续使用的状态，因此一并承接。
- **结转后允许继续补记旧年流水**。漏记时能保留真实交易日期和完整旧年报表。每次更正都会产生新账本期初是否联动的选择，影响期初稳定性，因此在结转前核对旧年、之后在新账本处理余额调整。
- **首版同时交付带凭证的单账本导出与恢复**。删除旧账本前可以将完整历史存放到其他位置。该能力还需要为 R2 附件提供打包、校验与独立恢复流程，单独交付可以保持年度结转的验收范围清晰。
- **按订阅金额判断是否需要账户**。可复用周期规则用金额识别账户依赖的思路。订阅金额也用于提醒展示，而且零金额的自动续费订阅仍需账户，因此以续费开关和实际绑定判断。

## Consequences

- 历史记录仍可检索。旧账本删除后，新账本可继续写入流水、冲减债务、核销次卡和执行规则。期初固定，旧年漏记对当前余额的影响用新账本中带说明的余额调整记录。
- 用户需在旧账本处理跨年误记和待办期次。如果定时任务已先在旧账本生成新年流水，预览会列出记录，确认前需人工核对。原币金额无法从历史数据确定时，用户需补录核实后的账户金额。
- 单次结转对旧账本做按日期的汇总并写入一批新台账记录。新增字段保存在现有表内。日常浏览与令牌鉴权不增加写库，Cron 维持每四小时一次。
- 带凭证的单账本备份和恢复属于独立流程。年度结转保留旧账本附件关联，新账本由自身数据支撑。

## Verification

- `test/core.test.ts` 核对元旦前后的年度边界和连续年度校验。
- `test/e2e.test.ts` 覆盖旧年度最后一秒、未来流水、软删除、历史账户原币缺口、外币转账、信用卡负值、归档账户、债务与次卡初值。
- Web 和 OpenAPI 测试覆盖所有者和查看者权限、确认后 Cookie 切换、旧账本查阅导出及写入拦截、并发确认、旧账本删除和新账本独立写入。
- 故障及并发测试覆盖结转批次中途失败、旧年待处理期次、周期规则和订阅抢在结转前后提交、只提醒规则、跨年试用及次卡续费与结转竞争。
- OpenAPI 回归验证有金额、无账户的提醒订阅可以结转并在新账本到期提醒。回归也覆盖非标准续费标记的旧年期次阻断、无账户跨年试用、结转归一化、活跃账本提醒、Web 与 OpenAPI 读写，以及无账户的自动续费订阅和绑定无效账户的提醒订阅。
- 冻结导入测试覆盖历史支出、收入、转账及元旦导入。结转预览逐分核对新账本的期初和实存余额。Web 与 OpenAPI 报表核对历史月份的活流水增量、外币账户估值和归档账户排除。
- 回归测试覆盖连续结转、指定债务与普通 FIFO 冲减、逐笔折算、Web 与 OpenAPI 外币结算、失败回滚、周期和订阅游标回退、并发报销、删除和建标签。
- 隔离的本地 D1 应用全部迁移，并验证结转后指定结算和普通还款共同冲减期初债务。
